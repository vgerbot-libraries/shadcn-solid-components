`AuthForm` provides a unified authentication workflow with mode switching (`login`, `register`, `reset`) and method switching (`password`, `phone-otp`, `email-otp`, `oauth`) in a single card.

`auth-form` does not include built-in mode switcher UI, so app code should control `mode` through external controls. For credential methods (`password` / `phone-otp` / `email-otp`), you can provide `credentialMethodControl` to render built-in tabs (config array) or custom UI (JSX element / render function).

## Usage

```tsx
import { AuthForm } from "shadcn-solid-components/hoc/auth-form"

<AuthForm
  enabledModes={["login", "register", "reset"]}
  enabledMethods={["password", "phone-otp", "email-otp", "oauth"]}
  credentialMethodControl={[
    { key: "password" },
    { key: "phone-otp" },
    { key: "email-otp" },
  ]}
  onSendOtp={async ({ method, target }) => sendCode(method, target)}
  onVerifyOtp={async ({ otpCode }) => verifyCode(otpCode)}
  onSubmit={(payload) => handleAuth(payload)}
/>
```

### Global form message

Use the controlled `message` prop to surface form-level feedback (submit failures, account locks, hints). If a callback (`onSendOtp` / `onVerifyOtp` / `onValidate` / `onSubmit`) throws and `message` is not provided, the error is rendered automatically as a fallback.

    <AuthFormMessageDemo />
  </div>
</ComponentPreview>

### Automatic error fallback

When `message` is not controlled, any error thrown from `onSendOtp` / `onVerifyOtp` / `onValidate` / `onSubmit` is rendered as an error alert automatically, and `onError` is notified. Errors without a message fall back to the `operationFailed` locale entry.

## API

### `AuthFormProps`

Extends `div` props (without `onSubmit`).

- `mode` / `defaultMode` / `onModeChange` — current auth mode and control hooks
- `method` / `defaultMethod` / `onMethodChange` — current auth method and control hooks
- `enabledModes` — allowed modes (`login`, `register`, `reset`)
- `enabledMethods` — allowed methods (`password`, `phone-otp`, `email-otp`, `oauth`)
- `credentialMethodControl` — credential method slot renderer, supports:
  - `AuthCredentialMethodConfig[]` (built-in tabs)
  - `JSX.Element`
  - `() => JSX.Element`
- The `credentialMethodControl` slot is hidden when current `method` is `oauth`
- OTP fields are inline-only (`target + verification code + send code`)
- `providers` — OAuth providers (`name`, `icon`, `onSelect`)
- `onForgotPassword` — callback for forgot-password action (shown in login + password mode)
- `onSendOtp` — send verification code callback
- `onVerifyOtp` — verify code callback before submit
- `onValidate` — custom validation hook before submit
- `onSubmit` — final submit callback with `AuthSubmitPayload`
- `message` — controlled global message (`AuthFormMessage | null`); pass `null` to hide
- `renderMessage` — custom renderer for the global message slot
- `onError` — called when an internal callback throws; without a controlled `message`, the error is also shown via the built-in alert
- `loading` — submit loading state
- `locale` — partial locale overrides

### `AuthSubmitPayload`

- `mode` — `AuthMode`
- `method` — `AuthMethod`
- fields: `email?`, `phone?`, `password?`, `newPassword?`, `confirmPassword?`, `otpCode?`, `rememberMe?`

### `AuthValidationResult`

- `valid` — boolean
- `errors` — field-level errors keyed by `AuthFieldErrorKey`

### `AuthFormMessage`

- `type?` — `"error" | "info" | "success" | "warning"` (defaults to `"error"`); maps to the matching `Alert` variant, with `"error"` rendered as `destructive`
- `content` — `JSX.Element`

### `AuthCredentialMethodConfig`

- `key` — `"password" | "phone-otp" | "email-otp"`
- `label?` — custom tab label (fallback to locale method label)
- `icon?` — optional icon node rendered before label
