`ConfigProvider` supplies shared configuration to nested components. Today the primary use is passing a **partial locale** object so built-in strings (for example in tables or date-related UI) resolve consistently across the tree.

## Usage

```tsx
import { ConfigProvider } from "shadcn-solid-components/components/config-provider"

<ConfigProvider locale={{ locale: "en-GB" }}>
  <App />
</ConfigProvider>
```

Pass only the keys you need to override; unspecified keys fall back to each component’s defaults. The top-level `locale` string is a common override for `Intl` formatting in components such as the date picker. Child components that call `useLocale()` read the merged locale from context. Outside a provider, `useLocale()` returns an empty object. The full `Locale` record shape is defined in the library source at `src/i18n/types.ts` if you are authoring objects by hand.

## API

- **`ConfigProvider`** — Props: `children`, optional `locale` (partial record of UI strings; typed as `Partial<Locale>` in source).
- **`useLocale()`** — Returns the current context value (`Partial<Locale>`), or `{}` outside a provider.

## Exports

- `ConfigProvider`, `useLocale`
- Types: `ConfigProviderProps`

### Nesting and overrides

Each nested `ConfigProvider` supplies a **new** context value for its subtree. Unlike the deep
merge behavior that is common in some React setups, this implementation uses the **nearest
provider**. If an inner provider passes `locale={{}}`, `useLocale()` in that subtree reads the
empty object instead of inheriting the outer fields.
