`ThemeProvider` stores a `ThemeConfig` (for example `base.radius`) in Solid context so components that call theme helpers can read consistent values. It is separate from color mode; pair it with your own CSS variables or Kobalte color mode as needed. The implementation reads only `children` and `defaultTheme`; `storageKey` appears on `ThemeProviderProps` but is not used yet—see `src/components/theme/index.tsx` for the current runtime contract.

## Usage

```tsx
import { ThemeProvider } from "shadcn-solid-components/components/theme"

<ThemeProvider defaultTheme={{ base: { radius: "md" } }}>
  <App />
</ThemeProvider>
```

Use `useTheme()` from `shadcn-solid-components/lib/use-theme` under the same provider to read `theme` or call `setTheme` / `setRadius`.

## API

- **`ThemeProvider`** — Uses `children` and optional `defaultTheme` (`ThemeConfig`). Other fields on `ThemeProviderProps` are reserved for future use.

## Exports

- `ThemeProvider`
- Types: `ThemeProviderProps` (`ThemeConfig` is defined in `shadcn-solid-components/lib/theme-context`)

## Examples

### ThemeProvider and `useTheme`

Use `useTheme()` inside the subtree to read `theme.base.radius`, update the token with
`setRadius`, and map it to Tailwind classes with helpers like `getRadiusClass("display")`. The
preview below is wrapped in its own `ThemeProvider` so it stays isolated from the docs site's outer
shell styling.

### Radius mapping by component category

Within the same `RadiusValue`, categories such as `form-control` and `display` map to different
rounded utility classes. See `radiusMapping` in `use-theme` for the exact table. This is useful
when buttons, cards, and other surfaces need slightly different visual hierarchy while still
following one shared radius token.
